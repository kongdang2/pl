# 코드지도 — 손익추정 웹 (kongdang2/pl)

> 처음 작성: 2026-11-04, 기준 커밋 `00b38c6`. 이 문서는 웹 사이트(로그인 화면·목록·엔진 띄우기·챗봇·수정요청)와 그것을 돕는 PC 도구·Supabase 를 다룬다.
> 엔진(손익추정 HTML) 내부는 PC `코드지도\코드지도_00~07` 이 기준이다.
> 줄 번호는 위 커밋 기준이므로 시간이 지나면 어긋난다. 함수 이름으로 찾는다.
> 코드를 바꾸면 이 문서의 해당 절과 §9 변경 이력을 같이 고친다. README.md 는 사용 설명, 이 문서는 개발·인수인계용이다.

- 저장소는 **공개**이고 화면 코드만 둔다. 실데이터(HTML·JSON)는 절대 올리지 않는다. 엔진·데이터는 로그인한 명단(`sk_members`)만 Supabase 에서 받는다.
- 빌드 단계가 없다. 정적 파일 그대로이고 main 에 병합하면 GitHub Pages(「pages build and deployment」)가 1~2분 안에 배포한다.
- `ver.txt` 의 번호를 바꾸면 index.html 이 그 번호를 붙여 js·css 를 새로 받는다. 휴대폰 캐시도 바로 바뀐다. **화면 코드를 바꿀 때마다 ver.txt 를 올린다.**

## 3. 엔진과의 약속 (바꾸면 웹이 깨짐)

엔진 쪽 이름을 바꾸거나 없애려면 **먼저 웹 담당에게 알린다**(PC AGENTS.md 에도 같은 규칙).

| 엔진 쪽 | 웹에서 쓰는 곳 |
|---|---|
| `window.__sonikWebBridge.info() / buildDb() / applyDb(db)` | 열기·저장·오프라인 파일 (웹연결패치.py 가 넣음) |
| `window.__SONIK_WEB__`, 저장 때 `postMessage({type:'sonik:save'})` | 저장 단추·Ctrl+S |
| `window.__EMPTY_ENGINE__`, `SYS_CHANGELOG` 첫 항목 `vNNN(-n)` | 빈 엔진 검사·버전 표시 |
| `__buildEngineHtml({embedData, emptyEngine, stripAdminBar})` | 오프라인 파일, 웹엔진갱신 빈 엔진 |
| `cpOpenReset`, `__dbBustCalcCaches`, `commitActiveEditBeforeSave`, `printCurrentMenu`, `switchZone/Site/Menu/Sub`, `S` | 열기 후 기준, 저장 전 편집 확정, 인쇄, 뒤로·앞으로 |
| `downloadBizplanEngine`, `exportPlanDb`, `p88PackYear`, `planDbPut`, `S._bvPrev`, `__BIZPLAN__`, `renderVarView`, `_bizApplySeed` 등 `_biz*` | 사업계획(bizplan-link.js). **a.download + URL.createObjectURL 방식으로 내려받는 것을 가로채므로 이 방식도 바꾸지 않는다** |

`engine-loader.js` 는 엔진이 열리기 전에 `__SONIK_WEB_FLAG__` 스크립트를 넣는다. 이 스크립트는 웹 표시를 켜고 localStorage·sessionStorage 를 메모리로 대체한 다음 자기 자신을 지운다. 그래서 엔진 안의 브라우저 저장은 새로고침하면 사라진다.

## 5. 저장 경로와 기기 보관

- 엔진: `engines/<ver>_<sha8>.html.gz`. 웹 저장본: `snapshots/<id>/r<N>_<uuid8>.json.gz`(저장마다 새 파일, 옛 것은 rpc 가 prune 목록을 돌려주면 지움). PC 올림: `snapshots/<id>.json.gz`.
- **경로가 바뀌지 않으면 내용도 같다.** 이 성질을 이용해서 기기에 보관한다(2026-11-03, #12·#13).
  - `SonikEngine.LocalCache`: IndexedDB `sonik-cache` / 저장소 `files` {path, blob, kind, at, size}. 엔진 최근 3개, 추정자료 최근 100개까지 두고 넘으면 오래된 것부터 지운다.
  - `fetchStored(path, kind, what)`: 보관본이 있으면 그것을 쓴다(서버에서 받지 않고 `sk_egress` 에도 적지 않음). 없으면 받아서 보관한다. 엔진 해시가 다르면 엔진 보관분을 지운다.
  - 웹 저장·PC 올리기 직후 올린 gz 를 바로 보관한다. 로그아웃하면 전부 지운다.
  - 보관은 기기·브라우저마다 따로이고 서버 공간은 쓰지 않는다. 브라우저 사이트 데이터를 지우면 함께 사라진다.
  - 보관하지 않는 것: 챗봇 첨부, 중계(PC)가 받는 파일.

## 7. 버전 규칙 (hong 2026-10-29·30)

- 웹 엔진 번호 = 오프라인 운영본 번호 + `-n`. 운영본 통과 후 자동으로 `-1` 이 되고, 웹에서만 고친 엔진은 `-2`, `-3` 으로 이어간다. 웹 파일은 PC 루트·`자동검증_실행용`·`보관\` 에 두지 않고 `웹테스트\` 아래에만 둔다.
- 엔진 계산·화면 변경은 웹에서 요청이 와도 **오프라인 다음 번호로 먼저** 만들고 Codex 통과를 받는다. 웹은 그 뒤에 따라간다. 웹에서 바로 고치는 것은 웹 전용 부분(로그인·목록·챗봇·수정요청·연결 통로)뿐이다.
- 스냅샷과 엔진의 버전 비교는 `-n` 을 뗀 번호로 한다(`sameBase`).

## 8. 고칠 때 확인할 것

1. 화면 코드를 바꿨으면 `ver.txt` 를 올린다.
2. `node -e "new Function(require('fs').readFileSync('app.js','utf8'))"`, `node --check engine-loader.js` 로 구문을 확인한다.
3. 표·권한을 바꿀 땐 `supabase/` 에 다음 번호 SQL 을 추가한다. 이미 적용된 파일은 고치지 않는다.
4. 엔진 약속(§3)에 손대야 하면 오프라인 쪽과 먼저 맞춘다.
5. README.md(사용 설명)와 이 문서 §2~§6 중 해당 절, 그리고 §9 를 고친다.
6. 데이터가 든 파일은 저장소에 올리지 않는다.
